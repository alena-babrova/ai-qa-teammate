**GitHub Actions (headless).** The workflow **target** **`__ISSUE_KEY__`** is **usually a Sub-task** (e.g. “create test cases for the story”). **`__STORY_KEY__`** is the **canonical story**: same as the target, **or** the **parent** when the target is a **Sub-task** (CI pre-resolves this). **All** text you use to **design** tests—**Description**, acceptance-style fields, scope—must come **only** from **`jira_getIssue(__STORY_KEY__)`**, never from the Sub-task’s **description** or **summary** when **`__ISSUE_KEY__` ≠ `__STORY_KEY__`**. Use **`__STORY_KEY__`** for **`generated/jira-tests/...` paths**, Jira **links**, and **Test summaries**.

1. Follow **`.cursor/rules/ai-test-generator.mdc`** (canonical schema, no interactive questions) and **`.cursor/rules/jira-test-create.mdc`** (project, **Test** type, Test Steps / Expected custom fields).
2. Follow **`.cursor/skills/jira-story-test-cases-md/SKILL.md`**, especially **`## Headless CI (this repository, GitHub Actions)`**, for how to derive tests from the story.
3. **Task (order matters):**
   - **Step A — Story only for requirements:** Call Jira MCP (e.g. **`jira_getIssue`**) for **`__STORY_KEY__`** first. Request at least **`summary`**, **`description`**, **`issuetype`**, **`parent`**, and—if your tool allows—custom fields for **Acceptance Criteria** / **DoD** on **that story issue**. **Test generation uses only this response** for scope: story **Description**, story **summary** (title context only), and story AC-style fields. **Do not** use the Sub-task’s **`description`**, **`summary`**, or other fields as a source of test scenarios when **`__ISSUE_KEY__` ≠ `__STORY_KEY__`**.
   - **Step B — Sub-task:** When the keys differ, **do not** **`jira_getIssue(__ISSUE_KEY__)`** to gather requirements. If the story’s **description** (and AC fields) are empty, document minimal coverage or note the gap in output—**never** backfill from the Sub-task body.
   - **Step C — Write files:** **`generated/jira-tests/__STORY_KEY__/tests.json`** and **`meta.json`** only—**never** put those files under **`__ISSUE_KEY__`** when the keys differ. Each **`summary`** must **include `__STORY_KEY__`** (see **`.cursor/rules/jira-test-cases-epmrpp-style.mdc`**).
   - **Step D — Jira Tests:** Create **every** Test issue via MCP, **link to `__STORY_KEY__`** only when it differs from the Sub-task. Then **`meta.json`** (`jiraPublish`, `mcpCreatedKeys`) per the rules.
4. Do **not** ask questions; do **not** put secrets in files.

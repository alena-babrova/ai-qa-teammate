**GitHub Actions (headless).** The workflow **target** **`__ISSUE_KEY__`** is **usually a Sub-task** (e.g. “create test cases for the story”). **`__STORY_KEY__`** is the **canonical story**: same as the target, **or** the **parent** when the target is a **Sub-task** (CI pre-resolves this). Use **`__STORY_KEY__`** for **`generated/jira-tests/...` paths**, Jira **links**, and **Test summaries**—not the Sub-task key when they differ.

1. Follow **`.cursor/rules/ai-test-generator.mdc`** (canonical schema, no interactive questions) and **`.cursor/rules/jira-test-create.mdc`** (project, **Test** type, Test Steps / Expected custom fields).
2. Follow **`.cursor/skills/jira-story-test-cases-md/SKILL.md`**, especially **`## Headless CI (this repository, GitHub Actions)`**, for how to derive tests from the story.
3. **Task:** Load **`__STORY_KEY__`** with Jira (`jira_getIssue`, etc.) and base cases on **that** issue’s description, AC, and scope—the **primary** source is the **story**, not the Sub-task summary alone. If you only see **`__ISSUE_KEY__`**, load it first: when **issue type** is **Sub-task** (or equivalent), use **`fields.parent.key`** as the story key and follow the same rules. **Mandatory path:** write **`generated/jira-tests/__STORY_KEY__/tests.json`** and **`meta.json`** only—**never** use **`__ISSUE_KEY__`** in that path when **`__ISSUE_KEY__` ≠ `__STORY_KEY__`** (CI verifies the story folder first; writing under the Sub-task key breaks the pipeline). Each **`summary`** must **include `__STORY_KEY__`** (see **`.cursor/rules/jira-test-cases-epmrpp-style.mdc`**). Create **every** Test issue, **link to `__STORY_KEY__`** only (the story), **via MCP**—**not** to the Sub-task **`__ISSUE_KEY__`** when it differs. Then add required **`meta.json`** (`jiraPublish`, `mcpCreatedKeys`) per the rules.
4. Do **not** ask questions; do **not** put secrets in files.
